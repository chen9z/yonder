# Yonder（仓库 herdc）：Herdr 的 Android 客户端

Yonder 是 [Herdr](https://github.com/herdrdev/herdr-app) 桌面版在手机上的同级客户端：连上 PC（局域网 SSH，
外网走 Tailscale）后，看到的是同一个世界——同样的 space、tab、分屏、终端和 agent 状态，改动双向实时同步。

## 关键事实（决定了架构）

- Herdr 桌面版本身不持有工作区：它是 herdr-core（`hc`）的客户端，经 `hc connect` 说 JSON-RPC 2.0，
  `hello {framed:true}` 后切到分帧模式（`[channel u32 LE][kind u8][len u32 LE][payload]`）。
- 共享结构（space → tab → 分屏树）存在 core 的 **`herdr-app` 文档**里（`doc.get` / `doc.set`，带版本 CAS）。
  每块屏幕的焦点、缩放、当前 tab、已读状态是**私有视图**，不写进文档。手机端读写同一份文档，
  就和桌面多屏完全同构。
- 终端都是 core 的终端；Herdr 用 `herdr.space` / `herdr.tab` 标签认领，`herdr.seen` 标签跨屏共享已读回合。
- core 没有 TCP 监听；远程访问的官方方式就是 `ssh host '…herdr-core connect'`（herdr 自己连远程机器也这么做）。
  本机 core 已经聚合了它添加的远程机器（`vps/t7` 这类地址），手机连上 PC 的 core 即可看到全部机器。

## 总体结构

```
┌──────────── Android (nsh, Rust) ──────────────┐        ┌──────── PC ────────┐
│ app/      UI：space/tab/分屏/终端/agents/面板  │        │ sshd               │
│   └ herdc-engine  无头控制器（移植自 window.rs）│  SSH   │  └ sh -c '…        │
│        ├ herdc-model  model/layout/mirror      │◄──────►│     herdr-core     │
│        ├ herdc-wire   JSON-RPC + 分帧多路复用   │  exec  │     connect'       │
│        ├ herdc-term   VT（alacritty_terminal）  │ channel│        │           │
│        └ herdc-ssh    russh：密码/密钥/主机指纹  │        │   herdr-core ◄─ herdr-app
└────────────────────────────────────────────────┘        └────────────────────┘
```

| crate | 职责 |
|---|---|
| `herdc-wire` | 与传输无关的 core 客户端：分帧编解码、调用/应答路由、attach 流与 credit 流控、`events.subscribe` 快照 + 事件应用 |
| `herdc-ssh` | russh 客户端：密码 / 私钥登录，主机指纹首次信任并固定（TOFU），exec 通道跑 Herdr 同款 pipe 命令行（支持 `HC_SESSION`） |
| `herdc-model` | **原样复用** herdr-app 的 `layout.rs`、`model.rs`、`mirror.rs`（Apache-2.0，见 NOTICE），文档读写与桌面逐字段一致 |
| `herdc-engine` | 无头控制器：把 window.rs 里的业务逻辑（命令、认领、对账、已读共享、提醒、文档 CAS 刷写）移植成可测试的逻辑 |
| `herdc-term` | 终端仿真：喂字节、出带样式的行快照、滚动回看、按键编码（应用光标键、bracketed paste）、查询应答走 AUTOMATIC_INPUT |
| `app` | nsh Rust 应用：手机/平板自适应 UI；终端用 canvas 画网格，隐藏输入框接软键盘，快捷键栏补 Esc/Ctrl/Tab/方向键 |

## 复刻范围

core 能力和内置 mods 的功能全部复刻，界面按手机重新设计；用户自定义的 JS mods 和 layout 不在手机上运行
（它们依赖 gpui-shell 运行时）。

| 桌面 | 手机 |
|---|---|
| spaces mod（侧栏、按机器分组、拖动排序） | 首页：按机器分组的 space 列表，状态点，长按重命名/关闭/移动 |
| tabs mod / terminals-bar | 没有 tab 条：左右滑切换，空间名下面一排小圆点（空间有两个以上 tab，或有收起的 tab 时）。当前的是一小段横条，其余的是淡色圆点，正在跑、等你、已完成的用状态色。点圆点切过去，长按重命名 / 收起 / 关闭；圆点后面是收起的个数（归档图标），点开选一个放回来（`tab.select` 会取消收起）。tab 的名字（读屏、切换时的提示、收起列表）去掉 agent 标题里和空间名或目录名重复的部分：`π - nova` → Pi，`修 bug | yonder` → 修 bug；只剩一两个字时用程序名。点顶栏标题切换空间 |
| 分屏树（row/column/stack） | 平板：真实分屏；手机：一次一个 pane + pane 切换条（和 tab 一样高，描边不填色以区分两条；shell 的 `me@host:~/a/b` 标题只写 `b`，重名的按位置加序号），缩放即全屏 |
| agents mod（working/blocked/done/idle，子 agent） | Agents 页：跨 space 列表，排序同桌面，不止一组时按 置顶 / 等你处理 / 完成 / 工作中 / 空闲 加小标题；点进 peek。blocked 的 agent 直接显示它问的最后几行和菜单选项（Codex / Claude Code 的编号菜单），点选项即发对应按键；“回复…”先按 Esc 离开菜单再发文字（菜单上直接回车会选中高亮的“是”）。工作区里，别处的 agent 等你时弹出同样的问题卡片，一直留到它不再等（正看着它时不显示），可点 ✕ 先放下 |
| peek（无 pane 的 worker） | Agents 页里子 agent 挂在父 agent 下；无 pane 的点开是 Peek 页，可 keep 成 tab 或跳到所在 pane |
| toast / 声音提醒 | 应用内 toast（blocked / done）。系统通知要等 NSH 发布通知 API（0.4.0 没有），后台常驻需要前台服务（打包的 APK 不能加 Java） |
| palette（命令面板） | 不做。以前有过（工作区“更多”→ 命令），它做的事 `+`、“更多”、搜索和长按菜单都有，删了；引擎的命令表（`herdc_engine::COMMANDS`）还在，app 照样按名字调用 |
| new-menu | 顶栏的 `+`：终端、本机探测到的 agent 程序（结果按机器缓存，先显示上次的再在后台重查）、新 space、新建/打开 worktree |
| machine-add | 首页菜单「Add a machine…」：电脑 `~/.ssh/config` 里的 host（含 Include）或手填，经 `machine.add` 添加；需要回答时提示在终端里跑的命令 |
| files / changes / worktree | 对应页面，经 `machine.exec`（mods 原样的命令行）实现，远程目录每 10 s 刷新（只在页面在最上层、app 在前台时；盖住或进后台就不问，回来立刻刷新一次，`nav::while_looked_at`）；打开的文件用 nsh-base 的只读 `Editor` 显示，按文件名高亮。Windows 上读文件用 PowerShell 的 `Get-Content -LiteralPath`（路径用 `tools::ps_quote` 包成单引号字符串），不走 `cmd /c type`（路径里的 `&` 会被当成命令）。新 worktree 的分支名先在手机上检查：以 `-` 或 `.` 开头、含 `..`、变成文件夹名后为空的都拒绝（`worktree::unfit`），不会建到 `.herdr/worktrees/<repo>` 外面 |
| help（快捷键表） | 手机没有快捷键，不复刻；命令页列出全部命令 |
| settings | 手机端设置：电脑（连接、添加机器、命令、断开）、字号（终端上也可双指缩放）、打字时适配、按键栏、语言（跟随系统 / English / 中文）、外观（跟随系统 / 浅色 / 深色）、Agents 排序、本机密钥 |

窗口类命令（最小化、最大化、桌面 app 更新、遥测）不适用于手机，不复刻。herdc 只做 Android：没有桌面入口。

## 关键设计决定

- **用 herdr-app 自己的模型代码**而不是按文档重写：文档格式、分屏增删的权重分配、命名规则、
  attention 规则都与桌面逐行一致，并且直接带上它们的单元测试。
- **SSH 是唯一的鉴权边界**，PC 端零安装。主机指纹首次连接后固定，变化时拒绝并提示；保存的电脑没有指纹时不拨号，报“主机密钥没有确认过”，要编辑连接重新核对（`link::login`）；
  密码加密保存在手机上，不往电脑上写任何东西（不自动配置公钥）。密码方式被拒就是密码错了，不再拿它试 keyboard-interactive：macOS 的 sshd 在密码失败后走 keyboard-interactive 会一直不回应（OpenSSH 客户端也一样）。只有电脑不接受 `password` 方式时才用 keyboard-interactive；登录最多等 30 s；连上电脑、交换密钥最多等 10 s（只接连接不说话的也算连不上）。保存的密码被拒（电脑改了密码）就不再重试（每次失败都会记到账户上），提示条上给“重新输入密码”。电脑上已经有手机公钥的（用户自己从设置页复制过去加的），就用钥匙登录。
  不支持 RSA 主机/用户密钥：russh 的 `rsa` 特性锁定的 `rsa` 预发布版与 NSH 依赖冲突，只支持 ed25519 和 ECDSA。
- **只 attach 可见的 pane**，离屏即 CLOSE，节省流量和电量；尺寸遵循 core 的“最后活跃的观看者定尺寸”，
  手机打开或切到一个终端就按手机的行列数接管（像 tmux 归最近用的客户端）：桌面的 145 列缩到手机上字小得没法看。代价是 Mac 上这个终端暂时变窄，桌面一打字就拿回去，手机改回旁观。设置里关掉“终端按手机尺寸排版”时才是旧的规矩：默认 observe，用户开始输入才接管尺寸。关掉时的两个例外：手机自己开的终端一开始就按手机的行列数；
  没人持有的终端（处在 core 的 headless 尺寸）也由手机接管，别的屏幕一打字就放手、改回旁观。
  手机开过哪些终端随“上次的界面”一起存下来，app 重启后这些终端仍按手机的行列数（以前重启后变成旁观，显示成桌面的大小）。
- **断线重连**：指数退避，重连后重新取快照、重新读文档、重新 attach（core 保证程序不受影响）。
  app 回到前台时先用 3 s 探一下线路，不通就立刻重拨（系统冻结进程后，断掉的线要等 keepalive 超时才会发现）。
  断线原因是网络时，app 每秒探一次电脑的 SSH 端口，一通就重拨，不等引擎的退避（最长 10 s）。
  退避从 0.5 s 翻倍到 10 s，订阅成功才重置（连上了但订阅不成，不会每 0.5 s 一直重试）；订阅流自己结束时隔 0.5 s 再订阅。连上后问 home 和窗口大小两件事同时问；这期间收到重拨就直接重拨。
  SSH 会话被网络悄悄断掉时看起来还开着：在它上面连 core 15 s 没结果就放弃这个会话，下次重新登录（“电脑太久没有回应”）。握手的第一行最多读 64 KB，登录 shell 打出一堆别的东西不会一直读下去。
  不再看的终端（stream 已放下、core 还没回 CLOSE）后来的数据直接丢掉，不再存进“早到”缓冲。
  机器列表只在 app 在前台时每 2.5 s 问一次，回到前台立刻问一次。终端的回滚缓冲从 1 万行降到 2000 行（和首屏带的一样多，`herdc_term::SCROLLBACK`）。
- **启动即回到上次的电脑**：退出前在哪台电脑就直接连哪台；在设置里“断开”离开后，下次从电脑列表开始。
- **界面语言**：文字以英文写在代码里（`t!("…")`），中文在 `app/src/i18n.rs` 查表；测试保证每个 `t!` 都有译文。
  引擎来的文字（提醒、确认框、命令说明、状态词）在显示时翻译；拼出来的（`"{name} needs you"`）按 `TEMPLATES` 里的模板认。
- **终端手势**：上下滑翻历史，左右滑（超过 80 pt，且横向为主）切到下一个 / 上一个 tab，双指缩放字号，长按选文字。Agents 页里看 agent 的终端不切 tab。tab 一换（滑动、圆点、命令），终端上方短暂显示“第几个 / 共几个 · 名字”。程序开了鼠标模式（lazygit、htop 等）时，轻点还会在那一格发一次左键点击（按下 + 松开），同时照常弹键盘。终端的每一行是一块单独的 canvas，它们不接触摸（`PointerEvents::None`），手指的位置才是相对整个终端算的（否则行号总是第一行）。
- **终端里的链接**：长按菜单最上面列出屏幕上离手指最近的最多 3 个链接（`herdc_term::Screen::links`：按显示内容找 `http(s)://`，折行的行接起来找（手机收到的屏幕是一行一行重画的，不带折行标记，所以写满整行的也当作接着下一行），去掉句末的标点和没配对的右括号；程序用 OSC 8 标的链接也算），点一下 `open_url`。
- **跳到终端**（`search::search_page`）：首页顶栏的 🔍。列出所有机器上的所有终端（core 的 `terminals`，含子 agent、没有窗格的），等你的在前，其余按空间的顺序；行的样子同 Agents 页（空间色块 + 程序图标，“空间名 在做什么”，第二行“tab · 机器”，子 agent 写“子 agent”）。终端没有 `herdr.space` 标签时（别的机器上的、子 agent）按 `where` 里的空间名找，再不行用它父 agent 的空间。输入的每个词都要出现在空间名、标题、程序、tab、目录、机器里。点一下：在窗格里的 `agent.focus` 过去，没有窗格的打开 Peek 页。
- **写消息**（`terminal::compose`）：按键栏 ⌄ 前面的 ✎，或长按终端菜单里的“写消息”，弹出底部面板：多行输入框（可以打字、粘贴、用输入法的语音输入），右上角“粘贴”把剪贴板接到后面。“发送”把整段作为一次粘贴（bracketed paste）发进去，250 ms 后再按回车（同自定义键）；回车的定时器挂在终端上，不挂在面板上，面板一关它就没了。没发出去就关掉，草稿留到下次在这个终端里打开。面板一关键盘也收起。图片和截图还不能发。
- **终端里的文件路径**：长按菜单里接着列出离手指最近的最多 2 个文件路径（`herdc_term::Screen::file_paths`：带目录或带行号、文件名有扩展名的，如 `src/a.rs:42:7`、`./b.py`、`/tmp/x.md`；网址和 `~/` 开头的不算，因为家目录在电脑那边才知道；中日韩文字不算路径的一部分，“改了src/a.rs。”这样贴着汉字的也能认出来）。太长时菜单里按目录截断，留下文件名和行号（“…/app/src/terminal.rs:400:5”）。点一下打开文件页：相对路径从这个窗格的当前目录算（没有就用空间的目录），绝对路径直接打开；说了行号就跳到那一行并高亮，Markdown 这时先显示源码。
- **断线提示条**：工作区里浮在终端上面，不占位置：它出现、消失时终端的行列数不变（以前每次重连都让远端终端改一次大小，桌面也跟着重排）。首页照旧排在列表上方。
- **外观**：颜色都是 `theme` 里成对的浅色 / 深色（`AdaptiveColor`），终端配色也有浅深两套（`theme::palette`）。默认跟随手机（`nsh.json` 的 `"appearance": "system"`）；设置 → 通用 → 外观可以固定成浅色或深色（`theme::Look`，存在 prefs 的 `look`），用 NSH 的 `set_color_scheme` 告诉平台，app 里的颜色、系统控件和终端（`theme::palette` 的 effect）一起换，不用重启。状态栏图标由每个页面按当前深浅色明确指定（`theme::status_bar`，浅色时深色图标），因为平台的默认样式跟手机走、不跟 app；电脑列表页因此也放进一个 `nav_page`。底部系统导航栏（三键那条）NSH 只在启动时按手机设一次，没有接口改，所以 app 和手机深浅不同时那条是另一种颜色（已知不足）。
- **字号**：按角色定，同一种角色在每一页都一样大，都用 `theme` 里的常量，不写数字（只有终端和文件预览跟着设置里的字号走）。参照 Apple 的文字样式，整体小一号：`TITLE` 20（页面自己的大标题：首页、电脑列表）、`HEADLINE` 18（面板、对话框标题）、`BODY` 16（输入框，面板里的选项和按钮）、`ROW` 15（列表行的标题，每一页都是）、`CALLOUT` 14（标题旁或行里的说明、小按钮）、`FOOTNOTE` 13（提示、空列表、出错）、`CAPTION` 12（行标题下的副标题、小标题、时间、卡片下的小字）、`SMALL` 11（角标、计数、底栏文字）。卡片离屏幕边 `INSET` 16，圆角 `CARD_RADIUS` 14：设置、电脑列表、Agents、跳到终端都一样。
- **动效**：少而快，都在 `ui` 里定：按下的按钮缩一点（顶栏图标 `PRESSED` 0.92，主按钮、次按钮 0.97，底栏 0.94），松开 `QUICK` 140 ms 弹回；开关的滑块滑过去、底色渐变。布局一变（折叠 / 展开分组、显示全部、换 Agents / Spaces、进出调整顺序）先调 `ui::smoothly()`（NSH 的 `animate_layout`，`SETTLE` 240 ms 先快后慢）：新出现的淡入，留下的滑到新位置；折叠的箭头转过去（`ui::chevron`），不是换一个图标。首页正在显示时，agent 状态变化让行换分组也这样滑过去（别的页面盖在上面时不动，免得动到终端）。系统设置里关掉动画时，这些都跟着关。
- **滑动操作**：Agents 的行可以往右拉（`TouchClaim::on_pan` 只认横向，竖着滑还是滚列表）：露出强调色的“置顶 / 取消置顶”，拉过 80 pt 底色变实，松手就做；不够远弹回。往左拉过 32 pt 松手（Android 先吃掉十几 pt 判断是不是横拉，门槛再高会觉得拉了没反应），行停在左边，露出两个按钮：“置顶 / 取消置顶”（强调色）和“停止”（红色），像 iOS 邮件。防误触：滑开本身什么都不做，要再点按钮（以前左拉到底就停止，翻列表时太容易误触，停止会丢掉 agent 手上的活）；点“停止”还要确认；同一时间只开一行（`agents::Swiped`），开了别的行、点这一行、往右推回 30 pt、列表滚动超过 6 pt（`on_scroll`）、重新画列表都会收起；有一行开着时按下别的行，只收起开着的那行，这一下不打开别的（同 iOS），打开时长按也不弹菜单。跟手的行不能加 `transition_transform`：每次移动都重开一段过渡，行会停在原处不动；松手后用十几帧的定时器自己退回去。拉着时行是“按下”状态，`active` 的半透明底会盖掉行的底色，所以不透明的底放在外面一层；拉住不动也不会再弹出长按菜单（Android 原生的长按不因横拉取消，headless 测不出来）。按设计不代发按键，所以没有“左滑发 Esc”。
- **主 Agent 页不要底部导航**：在主 Agent 的 tab 上，底部 nova / Agents / Spaces 那条不显示，整页给对话。顶栏最左边是返回箭头（和工作区的一样，带等你处理 / 已完成的数字角标），点了回到 Agents，底部导航随之回来。系统返回键也一样回到 Agents（以前是退出 app）：只在主 Agent 页、上面没盖别的页面时才接（`on_back_press`），别处的返回和手势预览不受影响。没选主 Agent 时的空页面也一样。
- **读对话时收起四周**（`chat::reading`）：在主 Agent 的对话里用手指往下读超过 24 pt，顶栏和子 agent 那一排一起收起（`ui::smoothly`），只剩对话和输入框；往回拉 24 pt、回到最顶上，或点状态栏下面那一条，就都回来。状态栏不藏：藏了以后，有挖孔摄像头的手机上 app 画不到那一条（窗口的挖孔模式在 NSH 的 Java 里，APK 改不了），顶上会留一条黑边。只认手指拖动和它甩出去的惯性（`on_scroll_drag_start` 到 `on_scroll_end`），新消息来了列表自己滚到底不算。离开主 Agent 的 tab、切到它的终端、打开别的页面，都会先恢复。系统导航栏改不了（NSH 只在启动时设一次）。
- **主 Agent**（`lead.rs`）：每台电脑可以指定一个 agent 作为主 Agent，你平时跟它说话，它再用 hc 把活分给别的 agent。记在 prefs 里（`leads`，按电脑），存的是终端地址、空间 id、空间名和程序（`Lead`）：终端重启后地址会变，所以地址找不到时，按同一个空间（先比 id，再比名字）里的同一个程序找回来，都找不到就说它没在运行。首页底栏三个 tab：主 Agent（名字用它的空间名，角标数它和它的团队里等你的）、Agents、Spaces；设了主 Agent，打开 app 就在这一页，不回上次的空间（`live::switch_connection` 读存着的 prefs，因为这时 prefs 的 context 不一定在）。这一页的顶栏换成它的色块、名字、程序和状态，点一下换人。下面依次是：团队（它启动的终端，按 herdr 的父子关系 `parent`，含孙辈；横排的小胶囊，带程序图标和状态，点了有窗格就过去，没有就 peek）、它的终端（`terminal::talk`，就是普通终端，点一下还是逐键输入，那时底下换成按键栏）、常驻输入框（多行，发法同写消息：整段粘贴，250 ms 后回车；发完不收键盘；没发的字放在全局，切走 tab 再回来还在）。键盘弹起时底栏让开。这一页长按终端的菜单里没有“写消息”，因为输入框就在下面。主 Agent 是 Pi 时，这一页默认是对话（`chat.rs`），顶栏多一个按钮在对话和终端之间切换（`chat::Talking`，全局）。

  对话读的是 Pi 自己的会话文件 `~/.pi/agent/sessions/<目录>/<时间>_<id>.jsonl`（`herdc_engine::tools::transcript`），不是终端上的字。找文件：终端标签 `alma.session` 是 `pi:id:<id>` 时按 id 找，（标签里的 id 还没有文件，比如 Pi 刚启动、还没说过话，就当成空对话，过一会儿再找，不拿别的会话顶替）；没有标签时取它的工作目录对应的文件夹（Pi 的规则：去掉开头的 `/`，`/`、`\`、`:` 换成 `-`，两头加 `--`）里最新的那个；标签变了（`/new`、重启）就重新找；没有标签时每个 turn 重新找一次（`/new` 只表现为更新的文件），文件没变就接着读。读：core 的 `file.read` 按行读，第一次只读最后 `TAIL` 800 行，之后只读新增的行；顶上的“显示更早的消息”再往前读 800 行（`transcript::earlier`，`Transcript` 记着读到的第一行 `start` 和最后一行 `read`，先读后读都放进同一张表，最后一条始终是文件里最靠后的那条），插进来时按插入前的高度和滚动位置把画面留在原处；最后一行没写完（没有换行）留到下次。它在工作时每 2 s 读一次，否则 10 s，`turn`、状态变了马上读，app 在后台不读。文件变短了就当成新文件重读。

  会话是一棵树（每条记着上一条的 `parentId`，回退、压缩会分叉），显示的是从最后一条往回走的那条线。显示的东西：用户消息（右边灰色气泡，带图片数；别的 agent 发来的见下）、回复的文字（`text_view` 的 Markdown，可选中，链接用系统打开）、工具调用（连续的合成一组，跨多条回复也合在一起；一行写“N 步 · 用到的工具”，一步时直接写命令或文件；点开逐条列出，失败的标红；点一条推出这一步自己的页面 `Route::Step`：上面是它拿到的全部输入（bash 的完整命令、write 的文件和内容、edit 拆成红绿两色的 `- `/`+ ` 行，别的工具是参数的 JSON，最多 2 万字），下面是结果（最多 6000 字，失败标红），都能选中，右上角“复制”）、`!` 命令（算一步工具）、压缩（分隔线）、出错（红字）、中断。思考过程和扩展自己的条目不显示。前后两条隔了 30 分钟以上（还有第一条前面），中间写时间：今天只写时刻，昨天写“昨天”，更早写月日（手机的时区，Android 上用 `localtime_r`）。列表贴在底部，往上翻了就不再自动滚，右下角出现 ↓，这时有新内容就在 ↓ 上加一个蓝点，点一下回到最新；键盘弹起时也保持贴底。你的气泡长按可以修改、复制，或者放进输入框。会话自己的变化（`session_info` 改名、`model_change` 换模型、`thinking_level_change` 思考强度）在说过话之后才显示成居中的灰字，之前的算开局设置。它在工作时底下转圈，后面是它正在做的那一步（最后一个还没有结果的工具调用）。

  别的 agent 经 hc 发来的话（`<hc from="t32 ivy">…</hc>`，Pi 当成用户消息记下）单独算一类 `Said::Told`：`from` 是地址，后面可能跟名字；没有 `from` 的是 hc 自己的通知（它启动的 agent 结束了）。有 `from` 的放在左边一张带边框的卡片（`chat::told`），上面一行“ivy 发来”和程序图标（名字先用标签里写的，没有就按地址在 core 的列表里找它的名字或程序；那个终端已经没了——同名的 agent 重启过，地址就变了——就按名字找；都找不到不画图标），正文是 Markdown，超过 5 行或 280 字只显示开头，“展开全部 / 收起”；长按复制。不能修改（不是你说的）。hc 的通知是居中的一行等宽灰字。数修改时后面还有几条消息（`later`）时它们也算，因为 Pi 的 tree 里它们也是 user 消息。

  折叠做完的一轮（`chat::items`）：一轮从你的话或 hc 发来的话开始，到下一条为止。做完的那一轮，最后一条回复照常显示，它前面的回复和工具（中间的话和步骤）收成一行 `Item::Worked`：“工作了 N 分钟 · M 步”（时长是这一轮第一条到最后一条的时间差，不知道就不写；没有步骤时写“N 条消息”），带一个转动的箭头，点一下展开、再点收起（展开的记在页面里，按这一行的 key）。展开、“展开全部”让列表变高，但对话本身没变（行数和最后一条都一样），↓ 上不加“有新消息”的蓝点。正在工作或在问你的那一轮不折。展开收起用 `ui::smoothly`。

  Pi 的状态行（`transcript::footer`）：每次读会话文件时也读一次它的终端屏幕，找最下面带 `<用量>%/<窗口>` 的那一行（还不知道时是 `?/<窗口>`），右边是模型（去掉 provider 的路径）和 `• 思考档位`。输入框上面一行小字（`chat::status_line`，`id:pi-status`）：模型 · 思考档位，右边一根 36 pt 的小进度条和“上下文 N%”，超过 70% 黄、超过 90% 红（和 Pi 自己的颜色一样）。读不到那一行就不显示；键盘弹起时也不显示。用会话文件里的 usage 自己算也行，但窗口大小在 Pi 的 models.json 里，屏幕上现成的更准。

  工作时列表底部写“正在工作 · 1:12”：从这一轮最后一条你的话或 hc 发来的话的时间起算，每秒更新（`set_interval`，随这一块一起结束）；刚发出去、会话里还没有那条时只写“正在工作…”，免得从上一轮算起。

  发送用 core 的 `terminal.send`（`hc send` 用的那个：粘贴、回车，会等人在别的屏幕上打完字），不 attach 终端；先显示一个半透明的气泡，下面写“发送中…”，core 收下后它在工作就写“已排队，这一步做完它就会看到”（Pi 在一步做完后才读新消息），否则写“已发送”；等会话里出现同样的话再换成真的（只认发出时还没有的那几条你的消息，按 id 记着，所以连发两次“继续”也不会马上消失；core 收下以后才算），core 收下 2 分钟还没出现（Pi 改了字）就不再等。没发出去提示原因，字退回输入框。

  它在工作、输入框是空的时候，发送键换成 ■（停止）：core 的 `terminal.interrupt`（对报状态的程序按 Esc，同终端里按 Esc），不确认，因为只是打断这一步，不会结束 agent；5 s 内没停下会提示。它在终端里等你（blocked）时，列表底部是一张红色卡片“nova 在问你”：里面画出它终端底部有内容的最多 14 行（`terminal::question`：一个只看不改尺寸的 viewer，颜色和终端一样，太宽就横向滚动），下面一排键 ↑ ↓ ← → 空格 Tab Esc ⏎，按了直接发到它的终端（viewer 第一次按键时按终端现在的大小接管，不改行列数）；这时输入框的提示变成“输入回答”，写的字粘贴进它的终端再回车（core 的 `terminal.send` 在 blocked 时会拒绝）。卡片右上角“打开终端”切到终端模式。

  修改消息：长按气泡 →“修改”，原文替换输入框里的字（原来的字记着，✕ 取消时还回去），输入框上面一条“正在修改这条消息”。它在工作或在问你时不让改（在问你时发送也会拒绝，不会被当成回答）。修改的状态和输入框里的字一样放在全局，切 tab、切到终端再回来还在；输入框按“电脑 + agent 地址”归属，换了电脑或换了主 Agent 就清空，旧草稿不会发给别人。退回去的过程中（气泡写“正在回到这条消息之前…”）不接受别的发送和修改，提示“稍等”。发送时数出这条之后还有几条你的消息（`later`，按显示的这条线），`transcript::rewind` 用 Pi 自己的键退回去：Ctrl+C 清空它的输入框 → 等看到它的输入框是空的、没有 tree 也没有别的问题（开着别的选择框就报“终端里开着别的东西”，什么都不敲）→ 敲 `/tree` 回车 → 等屏幕出现 tree（计数行 `(i/n)`，下面第一个非空行是横线，上面有 “Type to search”，所以对话里长得像 `(1/2)` 的字不会被认错） → 没有 `[user]` 就按 Ctrl+U（它是开关，按一次不对再按一次）→ 按 `later` 次 ↑ → 等选中的那一行（`› `，计数行上面）是这条：在当前线上（`•`），`user: ` 后面就是它的字（空白和换行都不算，中文在输入框里可以在任意处折行；屏幕截断时比前缀，至少 6 个字，屏幕上的不能比它长）→ 回车 → 问“Summarize branch?”就确认 `→ No summary` 再回车 → 等 tree 和问题都没了、它的输入框（最后两条横线之间）里是这条的字（太长时认 “Navigated to selected point”）→ 离第一次 Ctrl+C 至少 0.7 s（Pi 0.5 s 内两次 Ctrl+C 是退出）再按一次 Ctrl+C 清掉 → 照常 `terminal.send` 新的话。每一步最多等 4 s。失败分两种（`transcript::Rewound`）：回车之前出错，或回车后 tree 还开着（按 Esc 退出了），Pi 什么都没变，报“没能修改”，字和修改状态都还原；回车之后出错（Pi 已经退回去，旧消息在它输入框里），等够 0.7 s 再按 Ctrl+C 清掉它的输入框，报“已经回到那条消息之前，但新的话没发出去”，字放回输入框、修改状态去掉，再发一次就从那里接着。不用 `/fork`：它会换会话文件；不用扩展：只用 Pi 自带的。发送中的气泡写“正在回到这条消息之前…”。Pi 回去以后下一条记录挂在那条消息的上一条下面，页面跟着最后一条走，旧分支自然不显示。

  命令：`terminal.send` 不带调用方时不会给文字包 `<hc from=…>`，Pi 收到 `/name x` 就当命令执行（中文参数也行），所以命令和消息走同一条路，不用逐键敲。输入框以 `/` 开头、还没打空格时，上面列出 `OFFERED` 里开头对得上的命令（一行：等宽的 `/名字`、一句说明、在终端里才看得到结果的带终端图标），点一下放进输入框（`/name` 带空格），不直接执行。列表不放进滚动容器：键盘弹起时 Android 的滚动视图会先接走触摸、收起键盘，这一下就丢了；所以键盘在时最多列 5 行，不在时 8 行，多打几个字母找其余的。发送时第一个词是 Pi 自带命令（`PI`，含没列出来的）就按命令处理：它在工作就不发；列表里显示一行灰色等宽小字“/compact · 发送中… / 已发送”，3 s 后消失，不当成你的消息等它出现；`shown_there` 的（选择器、/session、/export 这类，以及不带参数的 /model、/thinking）发完切到终端。别的 `/` 开头（技能、扩展命令、路径）当普通消息发。

  输入框左边是发图片：系统相册选最多 4 张（长边缩到 2048 像素），用 core 的 `terminal.put` 放到它那台机器上终端旁边的文件夹里，路径接在输入框的字后面，agent 自己去读。输入框和草稿两种模式共用（`terminal::talk_bar`，`Offers` 里是停止和发图片；终端模式只有发图片）。

  主 Agent 页显示时，engine 的 `set_looking` 只看它（它的终端算“正在看”，`done` 变成已读）；离开这一页回到原来的规矩。底栏主 Agent 的角标：它或它的团队有等你的就数这个（红），否则它说完了还没看就是 1（蓝）。横屏时底栏变矮，不显示文字，输入框最高是屏幕高度的四分之一。别的 agent（Codex、Claude Code）还是终端加输入框。
- **图标**：顶栏和按钮都用 `assets/chrome` 里的 Lucide 线条图标（`ui::icon_button` 收图标名），不用 ‹ ⋯ ✕ 这类文字字符，各处粗细一致。
- **共用的小部件**：底部弹层（“更多”、选择菜单、写一段话）都是 `ui::bottom_sheet` + `ui::sheet_panel` + `ui::grabber`；Agents 和返回箭头上的数字是 `ui::badge`。画得比 44 pt 矮的按钮（“显示更早的消息”“打开终端”“更多选项”“粘贴”“提交”）用 `ui::reach` 把点击范围上下补到 44 pt，样子不变。tab 圆点没补：圆点挨着，补了会互相抢。整行可点的行都标成按钮，读屏念得出来。
- **选择面板**（`pick::menu`）：所有选项菜单（新建、切换空间、Agents 排序，tab / 空间 / agent / 终端 / 电脑的长按菜单，收起的 tab，语言）都用 app 自己的底部面板，样子同“更多”面板：每行前面是图标（线条图标、agent 的程序图标或空间色块），可分区，当前的那个加粗、行尾打勾，空间还带状态。关闭、删除、停止、离开这类会丢东西的项是红色。根页面挂一次（`pick::host`，电脑列表页也在它下面），同一时间只有一个，后一个来时前一个算取消。每行有 `test_id` `pick-<id>`，测试按 id 点。确认框（`ui::confirm` / `ui::agree`）还是系统的。
- **Agents 列表行**：每组放在一张圆角卡片上（`POPOVER`，组内行之间是从文字处开始的细线，子 agent 也在父 agent 的卡片里）。行前是空间的色块（和首页、顶栏同一个颜色），右下角带一个小的 agent 图标。第一行是加粗的空间名，后面是淡色的“在做什么”（`ui::without` 去掉标题里重复的空间名：`π - nova` → Pi，`修 bug | yonder` → 修 bug；只剩一两个字时用程序名）；按空间分组时空间名在小标题里，第一行只写在做什么。第二行是在哪台机器（本机写电脑名）。右边只留时间、置顶和状态。
- **工作区顶栏**：标题前是空间的色块（和首页同一个颜色），后面是空间状态（空闲不画）。第一行是“空间名 · 机器”（机器是淡色小字，状态在最后）；有多个 tab 时第二行是 tab 的小圆点，和名字的第一个字对齐。点第一行切换空间，长按是当前 tab 的菜单。正在看的空间被关掉（最后一个窗格、菜单）就回首页，不跟着 core 跳到下一个空间（可能在另一台机器上）。
- **电脑列表与连接表单**：电脑列表也是卡片（`ui::card`，和设置页同一个），一台电脑一张：电脑一行在上，上次的空间在下。连接表单里 Session 收在“更多选项”下（有值时展开）；主按钮连接时自己转圈、写着在做什么（“正在连接电脑…”“正在登录…”），只有出错才另起一行红字；在 app 里编辑连接有返回箭头，不再放“取消”。电脑列表页由 app 根部的 `dynamic` 画，页面里读信号要 untracked，不然信号一变整页重建（以前保存编辑后就是这样，`adding` 已被丢弃还被写）。
- **设置页**：首页右上角只有 🔍、⚙（Spaces 页多一个 +；主 Agent 页左边是它的名字），以前 ⋯ 菜单里的东西和 Agents 排序都在设置里。分组按常用程度排：电脑（电脑和线路状态、编辑连接、添加机器）、终端（字号、按手机尺寸排版、按键栏）、通用（主 Agent、语言、提醒、Agents 排序）、本机密钥、关于，最后单独一张卡片是“断开这台电脑”（会丢东西的放最底下，同 iOS 的退出登录）。字少：电脑行的副标题只写 herdr-core 版本；开关的解释放在卡片下面的小字（`ui::card_footer`），不挤在行里；公钥只有一行“复制公钥”，副标题是类型和最后 8 个字符，下面小字说放到哪。分组卡片（`POPOVER` 色的圆角卡片放在 `CANVAS` 上，组内行之间是从文字处开始的细线，小标题和卡片里的文字对齐），每行前面一个线条图标。电脑那一行右边是线路状态的圆点（连上绿、连接中黄、断开红）。复制密钥会提示“已复制”和要放到哪（`~/.ssh/authorized_keys`）。列表行而不是大按钮：去别的页的行带 ›，就地做事的行是强调色，会丢东西的（离开这台电脑）是红色。按键栏页同样：每个键的 ↑ ↓ ✕ 是淡色小图标，到头的那个变淡不可点，“恢复默认”是强调色的行；添加机器页里已添加的机器和 ssh 配置里的主机一样，右边是强调色的字（重命名 / 添加），点整行。开关是 `ui::toggle`：NSH 0.4 的 `switch` 只有行为没有样子，直接用什么也画不出来。
- **哪些提醒会弹出来**（`notes::Notify`，设置 → 通用 → 提醒）：默认“只提醒要紧的”：有 agent 在等你，和主 Agent 做完（它在回你的话）。别的 agent 做完不弹横幅，Agents 的角标和列表里看得到；一台电脑上十几个 agent 时，每做完一轮弹一次太吵。“全部”是以前的样子，“不弹出”只留你自己操作出错的提示。在等你的横幅留 10 s（以前一直留到你去看），之后靠角标。app 在后台时来的 agent 提醒直接丢掉，回来不会一下子冒一串。
- **提醒**（`notes.rs`）：一条横幅，固定在状态栏下面，键盘弹不弹都不动，不挡输入框和底部 tab 栏。一行：程序图标（右下角一个状态色的点：等你红、完成蓝），标题加粗，在等你的后面跟“需要你”，下面一行小字是空间 / 标签页；出错的红框，说明最多三行。只显示最新一条，其余在它下面露出一条边，写“还有 N 条”，点开全部（最新在上），“收起”收回；打字时只显示最新一条。点一下去它说的地方：主 Agent 切到它的 tab，别的 agent 进工作区并聚焦它；上滑超过 28 pt 或点 ✕ 收起。出现和消失都走 `ui::smoothly`。
  “正在看”只算真的在屏幕上的：主 Agent 的 tab 上是它，工作区上是当前标签页的窗格，Agents / Spaces 列表和盖在工作区上的页面（文件、设置…）上什么都不算（`engine.set_looking(Some(vec![]))`）。以前在列表页上也算当前标签页的窗格，那里的 agent 等你或做完都不会提醒。工作区返回键和首页 Agents 的角标：有等你处理的就数它们（红），否则数已完成的（蓝）。
- **tab 名字**：没起名的 tab 显示它里面 agent 的标题，不再只是一个数字；起了名的照旧。
- **密钥存放**：保存的密码和手机的 ed25519 私钥用 Android Keystore 里的 AES-GCM 密钥加密后再放进 NSH 的 Storage（`app/src/vault.rs`，JNI 调 `javax.crypto`）。Keystore 的密钥不出手机，所以备份或拷走的数据打不开；打不开时再要一次密码。NSH 生成的 manifest 带 `allowBackup`，改不了，所以靠加密而不是关备份。
  Android 12 以前拿不到 JVM，改用 app 自己的 AES-256-GCM 密钥（`ring`），放在 `no_backup` 目录、权限 0600，备份和换机迁移都不带它（前缀 `aside1:`）。
- **打包**：`app/apk.sh`（`--install` 顺带装到手机）：只打 arm64-v8a，fat LTO，用 `~/.config/herdc/release.jks` 正式签名（密码在 macOS 钥匙串 `herdc-release-keystore`）；签名不可用时停止，只有显式 `--debug` 才使用调试签名。名字 Yonder（包名 `dev.yonder.app`；以前叫 Herdr / `dev.herdc.app`，换包名不能覆盖升级）。桌面图标（`app/icon.png`）为深色底上的米白色终端笑脸和橙色状态点。仓库和 crate 仍叫 herdc，用户看不到。
  build 号由 `app/build-number` 或 `HERDC_BUILD` 指定，和提交号一起编进 app，设置 → 关于里显示；更新记录在 `CHANGELOG.md`。
  nsh-base 保留默认的 `highlight` 功能，文件查看器按文件名提供语法高亮。
- **诊断信息**：设置 → 关于 → 复制诊断信息：版本、系统、偏好、密钥怎么存的、电脑地址和用户、线路和各机器的状态、数量。不含密码和密钥。
- **CI**：`.github/workflows/check.yml` 在 Ubuntu 上装指定版本的 herdr-core（`HC_VERSION`），跑 `scripts/check.sh`。
- **没连上时的按键**：viewer 还没拿到终端时打的字先存着，连上再发；最多 4 KB，等了超过 10 s 就丢掉（那时屏幕上已经不是打字时看到的东西，一个回车可能执行别的）。
- **大量输出限速**：viewer 以 512 KiB/s 归还 credit（`Attach::pace`）。输出超过这个速度持续 1 s，就算“落后”，断开重新 attach，从当前屏幕开始，不再一个字节一个字节追 core 那边最多 4 MiB 的积压。省流量、省电，刷屏结束后 0.5 s 内看到最后的输出。
- **后台不收输出**：app 进后台时 viewer 放开终端（`Engine::set_shown(false)`），状态事件照收；回前台从当前屏幕重新 attach。以前后台刷屏 24 s 照样收 16 MB。
- **SSH 压缩**：优先 `zlib@openssh.com`，其次 `zlib`，电脑不支持就不压缩。
- **重画限频**：终端最多每 33 ms 画一次（约 30 fps）；刷屏时主要耗 CPU 的是绘制，不是解析。
- **外接键盘**：终端有键盘焦点时，Ctrl/Alt + 字母、方向键、Home/End/PgUp/PgDn、Esc、Tab、F1–F12 直接发给终端（NSH `on_key_with`，`When::Always`）；Ctrl+Q、F11 系统保留。
- **拖动分屏**：宽屏（≥ 720 pt）时，两个按权重分的窗格之间有一条可拖的分界线（`herdc_engine::seams`）。松手后两边按新位置重新分权重（`layout.resize`），每边至少一成；固定 px 的窗格不动。
- **先画上次的样子**：每台电脑连上并读完布局后，把它的 View 存起来（`seen.<id>`，有变化时最多 10 s 后存一次，进后台、断开时也存；超过 256 KiB 就不存 terminals）。
  再打开时先画这份，线路状态用实时的，读完新的就换成新的。电脑列表在每台电脑下列出它上次的 spaces，圆点是当时最需要关注的状态；点一个 space，连上后直接到那里；直接打开时回到上次看的 space。
- **手机自己的选择**：每个 space 看的是哪个 tab、焦点、缩放、收起的 tab、哪些提醒看过，由 engine 存进每台电脑一个文件（`Options.store`，像桌面的 `view.json`；最多每秒看一次有没有变化，engine 停下时再存一次），在 app 的 `files/views/<id 的十六进制>.json`（`link::view_file`）。重启后先画 `seen.<id>`，engine 读完布局再按这份恢复。删电脑时删掉；编辑连接改了 id 时，同一把主机密钥、用户和 session 才跟过去，否则删掉（`carry_view_in` / `forget_view_in` 按目录单测；release 包不能 `run-as`，手机上看不到这个目录）。app 私有目录统一由 `app_folder(子目录)` 求出（`files/views`、vault 的 `no_backup`）。
- **多个 session**：添加电脑时可以填 `HC_SESSION`（只允许字母、数字和 `._-/`，因为要拼进远端 shell），同一台电脑的不同 session 是不同的条目（`id` 末尾加 `/session`）。
- **Agents 和 Spaces 同一套样子**：每组一张卡片（`INSET` 16、`CARD_RADIUS` 14、`POPOVER` 底），卡片上方是同一个分组标题 `ui::group_heading`：折叠箭头、标题、数量，右边各加各的（Agents 折叠后的状态，Spaces 的 ＋ 或连接状态）。行高 52，行间细线从文字处开始，状态都用 `ui::status_mark`（空闲不画）。Spaces 的行要能拖，分隔线画在行里（`ui::row_line`），跟着行一起移动。
- **首页空间列表**：本机用电脑自己的名字，保留机器名大小写，本机在前、远程机器按名字排序。机器标题是“箭头 + 名字 …… +”（没连上时 `+` 换成状态的字），组之间留空；箭头可折叠整组空间，按电脑和机器存在 prefs，重启后保留；当前空间所在机器也允许折叠，选中空间不会自动展开。空间不显示标签页数量，只有非 main/master、不同于空间名及仓库目录名的分支才显示第二行，没内容就只画一行。同一台机器上有同名空间时，右边的淡字改成能区分它们的：目录不同写目录（家目录写“主目录”，单个 `~` 像是多出来的符号），同一个目录写里面跑着什么（如“Pi · Codex”），都一样才退回分支。行尾是空间里最要紧的 agent 状态（运行中转圈、等你红点、完成蓝点，空闲不画）。
- **Agents 列表**：「Needs you」只做状态提醒，点击可打开对应终端；列表与提醒浮层不读取终端问题，也不代发按键或回复。子 agent 已在别人的后代树中时不再占顶层行，置顶例外；已保留的后代优先取 AgentView 的状态，done 仍归 idle。主文字按桌面 Priority 视图显示空间加有意义的标签页或 agent 标题，数字自动名仅在重名时补上；空标题回退程序/app 名，远程行追加机器名；Pi 自带的标题 `π - <目录>` 不算有意义，显示成 Pi。本机的 agent 只有一行，第二行的机器名只给别的机器（本机的写了也是每行一样）；置顶分组里的行不再画 📌。长按菜单的标题和行里写的一样（“空间 · 在做什么”），不用原始标题（会带“| 空间名”）。读屏：每行是一个按钮，念“空间、在做什么、机器、状态”（空闲不念）；滑动的两件事（置顶或取消置顶、停止）也作为读屏操作提供，停止照样先问。空闲不画状态（同 tab 和空间）。按优先级排时空闲的超过 6 个，只列前 5 个，卡片最后一行是强调色的“显示全部 N 个”，展开后变成“收起”。状态旁显示变化距今的 <1m / Nm / Nh / Nd，每 30 s 刷新。时间用 core 记录的 `status_ms`（电脑上状态变化的那一刻，不是手机连上的时刻），没有时才用引擎自己看到变化的时间；旧缓存缺失时默认为 0（暂不显示时间）。
- **空间排序**：平时不画拖动柄。长按空间 → “调整顺序”进入排序模式：每行右边出现点阵拖动柄（淡色），顶栏只剩强调色的“完成”，换到 Agents 也会退出。拖动柄可以上下拖，按行高算移动几格，拖动时被越过的行让出位置，松手执行 `space.move`（只在同一台机器的 spaces 里移动）。
- **空间菜单**：长按 space 时，它是不是 git、是不是 worktree 先看缓存，没有就最多等 0.35 s；还没结果就先给出“工作树… / 文件 / 变更”（页面自己会说不是 git），后台查到的结果留给下次。
- **按键栏可编辑**：设置 → 按键栏：栏上的键可以前移、后移、移除，下面是可以加上的键（`\` `` ` `` `:` 等符号、Del、Ins、F1–F12）。最下面可以加自己的键：一段文字（`/compact`、`y`、`git status`），默认输完再按回车，显示成文字后面跟一个回车图标，读屏念“…，然后回车”。按键栏页的滚动视图用 `KeyboardTaps::Handled`，键盘开着时点 + 第一下就能加上。存成 `say:<文字>`，要回车的结尾带 `\n`；回车晚 250 ms 发，否则 Codex 会把紧跟在一串输入后的回车当成粘贴里的换行。存在 prefs 里。↵ 固定在最左，⌄（收起键盘）固定在最右，不随中间的键滚走。
- **按键栏的按法**：方向键、Del、PgUp/PgDn 按住 0.45 s 后每 50 ms 连发，松手即停（最多连发 400 次）。Ctrl / Alt 点一下只管下一个键（蓝框），连点两下锁定（实心），再点一下松开。
- **文件和变更**：列表可以下拉立即刷新（不用等 10 s 的定时刷新）；文件和 diff 的字号跟终端字号走。diff 页右上角是“第几个 / 共几个”和上一个 / 下一个文件，换文件替换当前页，返回直接回列表。
- **电脑列表**：每台电脑下面只列最急的 4 个空间（按原顺序），其余写“还有 N 个空间”；两台同名时副标题加上 `用户@地址:端口`。
- **焦点不共享**：手机上的焦点、放大、当前 tab 只记在本机引擎里，不发给 core，不会让桌面跟着跳。

## 会话与持久化边界

- `Engine` 的最后一个持有者释放，或显式调用 `close()`，会取消会话内的连接、后台请求和终端流。内部任务不持有会话所有权；关闭时清空发布给界面的客户端引用。
- 命令入口把 JSON 解析成有类型的参数，错误类型不得被当作缺省值。每条同步命令显式完成；异步回调被取消或因重连过期时返回错误，不会自动宣告成功。
- `docs::Slot` 独占布局同步状态及其转换规则，外层通过 `prepare`、`apply`、`connection` 等操作驱动同步。`state/documents.rs` 负责协调，`state/projection.rs` 负责构造视图。
- 缓存状态词通过有限枚举校验，不使用全局字符串驻留或永久分配。未知词使缓存解析失败，由实时状态重建界面。
- Android 上两种加密方式都失败时停止保存并报告错误。电脑列表先完整序列化，再替换存储；手机密钥对保存在同一个记录中，旧记录在新记录保存成功后移除。桌面无头测试保留显式的明文后端。

## 恢复后的版本与打包

原 Git 历史无法恢复，当前仓库从恢复源码建立新的基线。`recovery/` 中的恢复证据和归档保留在本地，不进入 Git。

`app/build-number` 从 50 开始，后续每次分发递增，也可通过 `HERDC_BUILD` 显式指定。版本号不依赖提交数量。

- `sh app/apk.sh --check`：仅检查版本参数。
- `sh app/apk.sh`：正式签名构建；缺少密钥或钥匙串解锁失败会停止。
- `sh app/apk.sh --debug`：明确选择调试签名。
- 追加 `--install` 才会安装到设备。正式密钥默认位于 `~/.config/herdc/release.jks`，可通过 `HERDC_KEYSTORE` 指定路径。
